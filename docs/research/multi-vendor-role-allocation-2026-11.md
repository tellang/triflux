## 다중 경로 독립 합의 사항

- **계획과 판단 고성능 배치, 실행과 탐색 경량 배치:** 3사 공식 가이드, 학술 실험(위임 계층 용량 확대 효과가 실행 계층의 약 4배인 "Think Big, Search Small"), 오픈소스 하네스, 커뮤니티, 영상 실험이 모두 일치한다.
  - Google 공식 가이드: Antigravity Orchestrator 기본값에서 계획과 감사는 `Carbon` 또는 `Argon`, 구현과 병렬 실행 워커는 `Hydrogen`을 권장한다.
  - Anthropic 공식 가이드: `Opus 5.5`를 기본 진입점으로 두고 `Fable 5.2`는 자문이나 상위 조정자, `Haiku 5.5`는 빠른 서브에이전트로 권장한다.
  - OpenAI 공식 가이드: `Sol 6.1`을 기본 구현 모델로 두고 `Luna`는 가벼운 탐색과 부분 편집 서브에이전트에 배치한다.
- **굵은 역할 경계 유지:** 모델 성능 차이가 실제로 유의미한 경계는 탐색, 판단, 실행, 검증, 리드, 소통 수준이다. 동일 모델로 역할 페르소나만 5개로 쪼갠 구성은 단독 실행보다 2~7배 느리고 점수도 낮았으며, 페르소나 문구 자체는 정확도를 바꾸지 못했다.
- **분해 가능한 작업에서만 경량 위임 유효:** 강하게 결합된 단일 과제를 `Haiku` 팀에 쪼개 맡기면 비용이 약 80% 늘고 시간도 1시간 이상 증가했다. 작은 모델 팀은 버그 오탐도 늘었다(`Haiku` 14/117, `Sonnet` 8/90, `Opus` 및 `Fable` 단독 0).
- **Fable 제한 배치:** Terminal-Bench 4.1에서 `Fable 5.2`와 `Opus 5.5`는 65.8% 동률이지만 작업당 비용은 `Fable 5.2`가 약 3.5배 높다. 반면 반복 코드 리뷰와 보안 감사 실측에서는 `Fable 5.2`만 점수가 상승해 만점을 기록했으므로 기본 구현이 아닌 계획 검증, 보안 리뷰, 최종 승격에만 쓴다.
- **리뷰어 최소 등급 보장과 새 세션 분리:** 리뷰어가 작성자보다 약한 모델이면 정답률이 91.4%에서 82.8%로 하락했다(JHU). 교차 벤더 리뷰 이득의 상당 부분은 작성 맥락과 분리된 새 세션에서 나오므로, 타 벤더를 우선하되 타 벤더가 모두 막히면 동일 벤더의 새 세션을 허용하고 작성자 이상 등급을 강제해야 한다.
- **워커 시작 시점 단일 선택:** 세션 도중 벤더를 바꾸면 프롬프트 캐시가 깨지고 도구 호출 스키마 차이로 파싱 오류가 발생한다(pydantic-ai 문서, 실무 보고). 벤더는 워커 시작 시점에만 결정한다.
- **작은 모델의 낮은 effort 전제:** `Haiku 5.5` max는 첫 응답 토큰까지 184초가 걸리고 `Terra 6.1` max는 프롬프트당 7~8분이 걸리지만 medium에서는 1분 미만이다. 작은 모델은 effort를 낮췄을 때만 속도 이점이 생긴다.
- **작업 단계 신호 기반 라우팅:** 프롬프트 문자열만 보고 모델을 고르는 범용 분류기 라우터는 실무에서 실패 사례가 많고 사용자 선택 덮어쓰기 불만(OMC #1135)을 유발했다. 작업 단계, 도메인 특성, 분해 가능성 신호로 소폭 조정하는 방식만 유효했다.

## 사용량 기반 전환 사례와 실패 유형

오픈소스 하네스와 LLM 게이트웨이 1차 코드에서 확인한 쿼터 기반 전환 방식은 다음과 같다.

- **t3code:** 사용률이 100% 이상이고 리셋 시각이 미래면 새 스레드 기본 모델을 폴백 모델로 교체한다.
- **agent-orchestrator:** Claude 오류 응답에서 리셋 시각을 파싱해 그 시각까지 Claude를 후보에서 빼고 Codex, Gemini 순으로 넘긴 뒤 리셋 시각 이후 자동 복구한다.
- **Hydra:** 토큰 예산 80%에서는 경고만 내고 90% 이상에서 등급을 조정한다.
- **OmniRoute, freellmapi, LiteLLM, Bifrost:** 계정별 5시간 창과 잔여 한도 비율(예: 잔여 20% 미만 감점, 100% 제외)로 후보 우선순위를 재정렬한다.

공개 구현체 이슈에서 반복 확인된 폴백 함정은 다음과 같다.

- 폴백 실행 자체는 성공했으나 호출자에게 결과가 전달되지 않는 버그(oh-my-opencode-slim #595, omo #5435).
- HTTP 200 스트림 본문 내부의 쿼터 소진 메시지를 감지하지 못하는 문제(mastra #21280).
- 내부 SDK 재시도와 외부 라우터 재시도가 곱해져 429 한 번에 요청이 9회 증폭되는 문제(crewAI, smolagents).
- 인증 실패(401, 403), 컨텍스트 창 초과, 안전 정책 거부를 쿼터 폴백 조건과 구분하지 않아 무의미한 타 벤더 재시도를 유발하는 문제(OpenHands).
- 가용 후보가 하나도 없는 역할을 조용히 약한 모델로 강등해 품질 사고를 내는 문제(oh-my-openagent는 가용 모델 부재 시 명시 실패 처리).

## 리드와 소통 역할 분석

- **리드 역할:** 리드에 상위 추론 모델을 두는 것이 하위 워커 전체의 추론 수준을 올리는 것보다 비용 대비 성능이 높다. 단, 워커 전체 실행 로그를 그대로 읽히면 토큰이 51.5% 늘고 품질이 오히려 떨어지므로 워커의 압축 요약만 전달해야 한다.
- **소통 역할 이원화:** 단순 상태 중계와 완료 알림은 응답 지연이 짧은 하 등급 모델(`Haiku`, `Luna`, `Hydrogen low`)이 적합하다. 반면 사용자 대면 최종 보고와 문서는 사람 선호도가 높은 모델이 유리하다. LMArena 글쓰기 사람 선호 순위는 `Carbon`(1542), `Argon`(1532), `Opus 5.5`(1528) 순으로 상위권이며, AI 판정 벤치마크(`Sol` 95.3, `Opus` 92.8, `Argon` 63.2)와 역전되므로 대면 글쓰기와 긴 문맥 문서는 사람 선호 기준을 반영한다.

## 경로 간 의견 차이와 기각 자료

조사 경로 사이에 의견이 나뉜 항목과 설계 확정 결과는 다음과 같다.

- `debugger` 소속 역할군: 구현과 묶는 시각과 원인 추론 중심의 판단군으로 묶는 시각이 공존했으며, triflux에서는 근본 원인 추론 비중을 기준으로 판단군(최상 등급)에 배치한다.
- 글쓰기와 디자인 역할군 분리: 구현 1위 모델(`Sol`, `Hydrogen`)과 시각 설계(`Opus`), 장문 문서 작성(`Argon`, `Opus`, `Terra`) 강점 모델이 다르므로 별도 역할군으로 분리한다.
- 교차 벤더 리뷰 효과 크기: 자체 측정 2~3%p 향상 보고와 새 세션 대조군 대비 차이 없음 연구가 공존하므로, 타 벤더 우선 배정을 기본으로 두되 타 벤더 전멸 시 동일 벤더 새 세션을 허용해 가용성과 독립 시선을 함께 확보한다.

검증 과정에서 기각한 부정확 정보는 다음과 같다.

- 자기 선호 편향 논문(arXiv:2604.06996)을 "같은 가족 모델 결함 50% 추가 승인"으로 확대한 서술: 원문은 "자기 자신이 생성한 출력"에 한정된 결과이므로 기각했다.
- `Terra` 단가를 $1.42/$7.11로 적은 2차 출처: OpenAI 공식 가격표($1/$5)로 정정했다.
- 외부 오픈소스 게이트웨이가 Jev를 직접 입력으로 쓴다는 미확인 문장: 1차 저장소 근거가 없어 채택하지 않았다.
- 미출시 모델명("Gemini 4 Krypton") 언급 영상: 공식 모델 목록(`agy models`)에 존재하지 않아 제외했다.

## triflux 라우팅 설계 반영 원칙

1. 에이전트 역할을 탐색, 판단, 실행, 검증, 글쓰기와 디자인, 리드와 소통 6개 역할군으로 묶고 각 역할군에 3사 벤더 우선순위 배열을 부여한다.
2. 모델 등급표는 실측 수치에 맞춰 최상(`Fable`, `Carbon`, `Opus`, `Astra`), 상(`Sol`, `Sonnet`, `Hydrogen`), 중(`Terra`, `Argon`), 하(`Haiku`, `Luna`) 4단계로 정렬하고 Antigravity에 `hydrogen` 가족을 추가한다.
3. 벤더 선택은 워커 시작 시점에만 수행하며 세션 도중에는 전환하지 않는다.
4. 읽기 전용 쿼터 스냅샷에서 사용률이 95%를 넘은 벤더는 등급을 유지한 채 후보 순서에서 한 칸 뒤로 미루고, 100% 소진이나 리셋 대기, 미설치, 비활성화 벤더는 리셋 시각까지 제외한 뒤 자동 복구한다.
5. Jev는 신뢰도 0.85 이상일 때 작업 단계, 특성, 분해 가능성 신호로 벤더 순서를 최대 한 칸만 조정한다.
