# ADR-0046: 지켜지지 않는 리드 규칙은 triflux mod 훅으로 강제한다

## 컨텍스트와 문제 (Context)

tfx-lead 스킬에는 "결과를 받은 팀원은 바로 닫는다" 규칙이 있다. 그런데도 2026-10-23 리드 세션에서 끝난 Agent 도구 팀원 10개가 tmux pane 과 Claude 프로세스, 프로세스마다 MCP 서버 5개를 쥔 채 남아 메모리 압박 2 를 만들었다. 닫자 바로 1 로 내려갔다. 문서만으로는 규칙이 지켜지지 않았다.

같은 날 "긴 지시는 파일로 보낸다" 는 규칙은 있었지만 보고 쪽 규칙은 없어서, 서브에이전트 결과와 피어 메시지가 길면 리드 문맥을 그대로 차지했다.

## 결정 (Decision)

- 리드 규칙 가운데 mod 훅이 판정 신호를 가진 것은 문서와 함께 triflux mod 로 강제한다. 강제는 `/tfx-lead <역할>` 이 남긴 리드 표지(`tfx.lead.<세션 ID>`)가 있는 세션에서만 돈다. 사용자가 직접 띄운 세션과 리드가 아닌 세션은 건드리지 않는다.
- 이번에 구현하는 것은 두 가지다.
  - 보고 크기 상한 4000자. `session.receive`(origin `peer`, `peer-send-message`)로 들어오는 피어 메시지와, `session.append` 로 리드 메인 대화에 쌓이는 서브에이전트 결과(origin 이 Agent 도구 결과이거나 `task-notification`)를 본다. 넘으면 앞 800자와 본문의 파일 경로 목록(최대 20개)만 남기고 "원문 <N>자, 결과 파일 참조" 줄을 붙인다. 경로가 하나도 없으면 원문을 잃으므로 자르지 않고 경고 토스트만 띄운다. Agent 결과의 800자 이하 블록(하네스가 붙이는 agentId, usage)은 그대로 둔다. 요약 모델 호출은 하지 않는다.
  - 끝난 팀원 정리. 쉬기 시작한 팀원을 알리는 이벤트는 터미널 pane 팀원에게 없다(`turn.complete` 가 pane 팀원에는 오지 않는다). 그래서 2분마다 `$.agent.list()` 를 재 이름 있는 `idle` 에이전트(리드 메인 대화가 띄운 것)의 유휴 시작 시각을 기록한다. pane 팀원은 pane 이 닫혀도 명단에 `idle` 로 남으므로, 리드가 tmux 안이면 `tmux list-panes -a` 의 `--agent-id` 값으로 살아 있는 pane 만 센다. 10분 넘게 쉰 팀원이 생기면 리드 자기 세션에 피어 메시지(`tfx-peer self`, 실패하면 `prompt.submit`, ADR-0043 경로)로 "열린 팀원 N개: 이름 유휴 분" 을 보낸다. 알린 뒤 10분이 더 지나도 열려 있으면 팀 주소가 있는 팀원에게 `$.tool.call` 로 SendMessage `shutdown_request` 를 한 번 보낸다. 팀원이 거절할 수 있고, mod 는 pane 을 직접 닫지 않는다. 요청이 실패하면 리드에게 알린다.
  - 리드 메인 대화의 모델이 SendMessage 를 그 팀원 이름이나 팀 주소로 보내면(`tool.call`, `next.origin.plugin === 'engine'`) 유휴 시계를 바로 지운다. 2분 주기 사이에 다시 일하고 끝난 팀원이 처음 시각으로 종료 요청을 받지 않게 한다. mod 자신의 shutdown_request 는 plugin 출처라 리셋하지 않는다.
  - 리드는 `/tfx-keep <이름>` 으로 일부러 남길 팀원을 표시한다. `$.store` 의 `tfx.keep.<세션 ID>` 에 두고 `/clear` 뒤에는 리드 표지처럼 새 ID 로 옮긴다. 표시한 팀원은 알림에 "(유지)" 로 나오고 종료 요청에서 빠진다.
  - 파일 경로는 `/`, `./`, `~/` 로 시작하고 확장자나 알려진 디렉터리(.omc, docs, scripts, tests, hud, mods, bin, packages)를 담은 것만 센다. 숫자와 점뿐인 것(버전 문자열)은 빼고, 끝에 붙은 한글 조사와 문장부호는 떼고 판정한다.
- 나머지 강제 후보는 아래 표로 남기고 구현하지 않는다.

| 규칙(tfx-lead 절) | 훅 | 판정 신호 | 강제 방식 | 상태 |
| --- | --- | --- | --- | --- |

## 검토한 대안 (Considered Options)

- **문서 규칙만 두기**: 지금까지의 방식이다. 오늘 사고가 문서만으로는 지켜지지 않음을 보였다. 기각.
- **키워드 기반 자동 라우팅을 되살리기**: 프롬프트 키워드로 스킬이나 경로를 주입하던 방식은 ADR-0023 으로 제거했다. 판정 신호가 프롬프트 문자열뿐이라 오탐이 많았다. 이번 강제는 도구 호출, 명단 상태, 메시지 길이처럼 구조화된 신호에만 건다. 기각.
- **유휴 팀원을 바로 자동 종료하기**: 끝난 팀원은 SendMessage 로 재개할 수 있게 살아 있다. kill-pane 으로 닫은 팀원은 이름으로 메시지를 보내도 되살아나지 않으므로, 리드가 리뷰 지적을 되돌리려는 재확인 메시지를 막는다. 그래서 알림을 먼저 보내고, 10분 뒤에도 거절할 수 있는 shutdown_request 만 보낸다. 기각.
- **tmux pane 만 재기**: 지시서가 이벤트가 없을 때의 폴백으로 둔 방식이다. pane 시작 명령만으로는 팀원이 일하는지 쉬는지 알 수 없다. `$.agent.list()` 의 `status` 가 그 신호를 주므로 명단을 기준으로 하고, tmux 는 닫힌 pane 을 걸러내는 데만 쓴다. 기각.
- **긴 보고를 모델로 요약하기**: 요구가 금지했고, 결과 파일이 원문을 갖고 있으므로 필요 없다. 기각.
- **경로가 없어도 자르기**: 결과 파일이 없는 보고는 잘린 부분을 되찾을 곳이 없다. 경고만 하고 워커에게 파일로 보내게 한다. 기각.

## 결과 (Consequences)

- 리드가 팀원을 닫지 않아도 10분 안팎에 알림이 오고, 20분 안팎에 팀원에게 종료 요청이 간다. 명단을 2분마다 재므로 유휴 시작 시각은 최대 2분 늦게 잡힌다.
- `name` 없는 백그라운드 서브에이전트는 `idle` 이 되지 않고 끝나면 프로세스를 따로 쥐지 않으므로 대상이 아니다. 팀 주소가 없는 이름 있는 에이전트는 알림만 받는다.
- 리드가 tmux 밖(iTerm2 분할 등)이면 닫힌 pane 을 걸러내지 못해, 닫은 팀원이 명단에서 빠질 때까지 한 번 알림에 섞일 수 있다.
- 4000자를 넘는 보고는 리드 문맥에 앞 800자와 경로만 남는다. 리드는 결과 파일을 읽어 원문을 본다. 작업 알림(`task-notification`)의 행 형식과 Agent 결과의 하네스 블록 배치는 d.ts 기준이며, 설치 뒤 실제 세션에서 잘린 모양을 한 번 확인한다.
- 되돌릴 조건: 호스트가 팀원 유휴 이벤트나 종료 함수를 mod API 에 열면 폴링을 그것으로 바꾼다.
