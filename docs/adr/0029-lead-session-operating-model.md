# ADR-0029: 리드가 세션의 생성부터 종료까지 소유한다

## 컨텍스트와 문제

한 리드 에이전트가 여러 Claude, Codex 세션을 지휘하는 운영이 일상이 됐다. 2026-10-06부터 07까지 Codex 리드 하나가 Claude 세션 여럿을 지휘한 기록에서 다음이 확인됐다.

- 리드가 완료 확인을 `tmux capture-pane` 직접 호출 225회와 ACK 파일 폴링으로 했다.
- 받는 쪽 세션은 compact나 승계 없이 60만~97만 토큰까지 찼고, 한 세션은 작업 도중 `Prompt is too long`으로 실패했다.
- 긴 프롬프트를 tmux에 직접 입력하면 화면이 깨졌다.
- 누가 세션을 닫을지 정해져 있지 않아 다 쓴 세션이 남았다.

## 결정

세션을 띄운 쪽(서브에이전트를 부른 세션이든 여러 세션을 지휘하는 리드든)이 그 세션의 생성, 이름, 컨텍스트, 승계, 종료를 책임진다. 판단 기준의 정본은 `skills/tfx-live/SKILL.md`의 "리드 운영" 절이다. 이 ADR은 그 구조를 고정한다.

- **이름**: 새 세션은 `<월>.<일> <주제>`로 이름을 붙이고, 승계 세션은 기존 이름 뒤에 ` 2`, ` 3`을 붙인다.
- **컨텍스트**: 리드가 수동으로 compact한다. autoCompact는 사용자 의도로 꺼 두며 리드가 켜지 않는다. 개입 시점은 공식 모델 창 대비 비율로 판단한다.

  | CLI | 경고 | compact | 신규 배정 중지와 handoff | 전송 거부 |
  | --- | ---: | ---: | ---: | ---: |
  | Claude Code 1M 모델 | 60% | 75% | 85% | 90% |
  | Codex | 15% | 18% | 20% | 22% |

  비율은 공식 권고가 아닌 운영값이며 모델 문서가 바뀌면 갱신한다.
- **승계**: 담당, CLI, 모델이 바뀌거나 긴 작업이 창을 넘기면 handoff 파일을 쓴다. 승계 세션이 파일 경로를 확인(ACK)한 뒤에만 원 세션을 종료한다.
- **종료**: 결과와 인계를 확인한 즉시 닫는다.
- **관전**: 사람은 tmux 세션과 `tmr`로 본다. 리드가 기계적으로 보내고 받는 쪽은 `tfx-live ask --no-wait`와 `wait --request-id`로 나눈다.
- **지시**: 작업자 지시는 지시서 파일 경로로 보낸다. 긴 프롬프트를 직접 입력하지 않는다.
- **교차 리뷰**: 리뷰어는 작성 모델과 다른 모델로 한다.

## 검토한 대안

- **세션 자체 관리(autoCompact에 맡김)**: 리드의 부담이 없다. 그러나 압축 시점과 보존 내용을 통제할 수 없고, 사용자가 의도적으로 꺼 둔 설정과 충돌한다.
- **종료를 사용자나 훅이 일괄 정리**: 구현은 단순하다. 그러나 결과 확인 전에 닫거나 반대로 오래 남기며, 승계 ACK 같은 소유권 정보를 알 수 없다.
- **리드 소유(채택)**: 생성한 쪽이 맥락과 소유권을 알고 있어 판단이 가장 정확하다. 대신 리드가 비율과 절차를 지켜야 하므로 `tfx-live`의 가드(경고, 거부)로 보조한다.

## 결과

- `tfx-live`에 `ask --no-wait`, `wait --request-id`, `compact`, `stop --short`, `start --name`과 받는 쪽 컨텍스트 가드가 들어간다(PR #590).
- 비율 표는 운영 경험에 따라 바뀔 수 있어 ADR이 아닌 스킬 문서가 정본이다. 숫자를 바꿀 때 이 ADR은 고치지 않는다.
- 세션 수명 규칙을 어기는 리드는 코드로 막을 수 없다. 규칙과 가드에 의존한다.
- 근거 자료는 `docs/research/tfx-live-context-policy-2026-10.md`에 있다.
