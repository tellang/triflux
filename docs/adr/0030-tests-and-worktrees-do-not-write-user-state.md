# ADR-0030: 테스트와 worktree는 실제 사용자 상태에 쓰지 않는다

## 컨텍스트와 문제

2026-10-08 하루에 같은 종류의 사고가 세 번 났다. 모두 개발 중인 코드가 실제 사용자 홈의 상태를 고쳤다.

1. 실제 `HOME`으로 전체 테스트를 돌렸더니 `~/.codex/config.toml`의 MCP 항목이 지워졌다.
2. worktree에서 `npm ci`를 실행하자 postinstall이 setup을 재귀로 실행해 프로세스가 557개까지 늘었다.
3. worktree에서 실행한 `ensure-codex-hooks`가 전역 `~/.codex/hooks.json`을 그 worktree의 경로로 덮어썼다. worktree를 삭제하자 모든 Codex 세션에서 훅이 실패했다.

공통 원인은 스크립트와 테스트가 "지금 어디서 실행되는지"를 구분하지 않고 전역 설정 경로를 그대로 쓴다는 점이다.

## 결정

개발 중인 코드가 전역 사용자 상태에 닿지 못하게 네 겹으로 막는다.

- **테스트 홈 격리**: 테스트는 `HOME`, `CODEX_HOME`, `XDG_CONFIG_HOME`을 임시 디렉터리로 바꿔 실행한다. 공용 테스트 헬퍼가 이 설정을 제공하고, 새 테스트는 직접 홈을 읽지 않는다.
- **스크립트 설치 차단**: 개발 체크아웃(worktree 포함)의 의존성 설치는 `--ignore-scripts`로 한다. postinstall은 설치본 경로에서만 의미가 있다.
- **전체 테스트 격리 실행**: 전체 테스트 스위트는 로컬 사용자 환경이 아닌 원격 호스트(예: m2) 같은 격리 환경에서 돌린다. 로컬에서는 변경 영역의 테스트만 임시 홈으로 돌린다.
- **전역 쓰기 가드(제안)**: 전역 설정을 쓰는 스크립트(`ensure-codex-hooks`, setup 계열)는 자기 경로가 설치본 경로가 아니면 쓰기를 거부하고 이유를 출력한다. 가드의 세부 판정 방식은 구현 PR에서 정한다.

## 검토한 대안

- **사고마다 해당 스크립트만 고침**: 변경이 작다. 그러나 전역 경로를 쓰는 스크립트가 많아 같은 사고가 다른 스크립트에서 반복된다.
- **개발용 별도 사용자 계정이나 컨테이너**: 격리가 가장 강하다. 그러나 이 저장소의 대상(로컬 CLI, tmux, Keychain)을 컨테이너로 재현하기 어렵고 운영 부담이 크다.
- **네 겹 방어(채택)**: 테스트 쪽 격리와 스크립트 쪽 거부가 서로 다른 실패 지점을 막는다. 가드가 설치본 경로 판정을 잘못하면 정상 설치가 거부될 수 있어 판정은 구현 때 검증한다.

## 결과

- 로컬 전체 테스트는 기본 워크플로에서 빠진다. 릴리스 전 확인은 원격 실행 결과로 한다.
- 홈을 직접 읽는 기존 테스트(`nativeProxy`, `hub-server` 등)는 임시 홈을 쓰도록 고친다.
- 복구 비용: 사고 2, 3은 원인 파악에만 반나절이 들었다. 가드는 이 비용을 오류 메시지 한 줄로 줄이는 것이 목적이다.
- 가드의 구현과 임시 홈 헬퍼는 후속 PR로 나눈다. 그 전까지 이 ADR은 `proposed`다.
