# ADR-0057: remote-send 사전 승인을 send 승인과 별개의 선택 항목으로 둔다

## 컨텍스트와 문제 (Context)

`tfx-peer remote-send`는 로컬 `send` 승인 범위에서 일부러 뺐다. 로컬 승인이 원격 실행까지 넓어지지 않게 하려는 것이었다. 그 결과 원격 전송은 매번 실행 권한을 받아야 하고, 무인으로 도는 세션은 회신을 보내지 못한다.

## 결정 (Decision)

우리는 `remote-send` 사전 승인을 `triflux setup`의 별개 선택 항목으로 둔다.

- `send` 승인이 있고 유효한 원격 목적지가 있을 때만 묻는다. 실제 동의 질문에 홈의 `~/.config/triflux/hosts.json` 절대경로와 각 목적지의 주소, SSH 사용자, 포트를 표시한다. 기본값은 거절이다.
- 홈 절대경로의 `tfx-peer-remote remote-send`에 Claude와 Codex 규칙을 연결한다. 전용 래퍼에 등록 파일과 동의 파일의 절대경로를 고정하고, 동의 파일에는 승인한 호스트 이름과 목적지 값을 저장한다.
- 전송 직전에 선택한 호스트의 정규화된 주소, SSH 사용자, 포트를 동의 파일과 대조한다. 등록 파일이나 동의 파일을 읽을 수 없거나 선택한 목적지가 승인 범위를 벗어나면 SSH 전에 거부한다. `send`의 기존 래퍼, 규칙, 동의 계약은 보존한다.

## 검토한 대안 (Considered Options)

- **`send` 승인에 `remote-send`를 합치기**: 질문이 하나로 줄지만, 기존 동의의 뜻이 원격 전송까지 넓어지고 승인 계약이 바뀌어 모든 사용자가 다시 동의해야 한다.
- **등록 파일의 현재 목록 전체에 승인 적용**: 등록 파일 경로를 고정해도 파일을 수정하는 것만으로 동의 범위가 넓어진다.
- **목적지 호스트마다 허용 규칙 만들기**: 접두 규칙은 옵션 순서에 의존하고 이름이 가리키는 주소, 사용자, 포트의 변경을 검증하지 못한다.

## 결과 (Consequences)

- 목적지를 추가하거나 주소, SSH 사용자, 포트를 바꾸면 대화형 setup에서 명시적으로 다시 승인한다. 다른 호스트를 추가해도 이미 승인한 목적지의 값이 같으면 계속 보낼 수 있다. update, 비대화형, CI, postinstall에서는 원격 승인 설정을 쓰지 않는다.
- SSH 사용자를 명시한 Darwin과 Linux 호스트를 승인할 수 있다. 포트를 생략하면 22를 사용한다. 승인 경로는 OpenSSH에 주소, 사용자, 포트를 명시하고 호스트 이름 정규화와 연결 재사용을 끈다. DNS, 프록시, 인증, 호스트 키 검증은 기존 SSH 연결 정책을 따른다.
- 기존 `tfx-peer remote-send`는 명령별 실행 권한으로 사용할 수 있다. 로컬 어댑터를 철회할 때는 원격 allow, 규칙, 래퍼, 동의 파일을 함께 제거한다.
