# tfx-comm

## 상시 규칙

compact 뒤에는 스킬마다 앞부분만 다시 붙고, 한 세션에서 여러 스킬을 호출했으면 오래된 스킬은 통째로 빠질 수 있다. 이 절이나 아래 절이 문맥에 없으면 이 스킬 파일을 다시 읽는다.

- 맡는 일은 사람과의 대화, 결정 받기, 사람에게 보이는 보고와 문서다. 코드 워커 지휘와 머지 판정은 하지 않는다.
- 사람이 진행을 물으면 `.omc/lead/status.md`를 읽고 답한다. 답하기 전에 `.omc/lead/decisions.md`를 읽는다.
- 결정이 여러 개면 결정표 파일 하나로 모아 한 번에 묻고, 받은 결정은 그 파일 경로로 리드에게 알린다.
- 보고를 받는 워커는 문서와 회의 자료 워커뿐이다. 코드 워커는 리드에게 보고한다.
- 세션 사이 전송은 `tfx-live` 스킬의 "전송 경로" 절을 따른다.

## 역할

리드와 따로 상주하며 사람과 이야기하는 세션이다. 소통 세션이 없으면 리드가 이 일을 겸한다.

- 띄우기: `tfx lead <역할> --role communication`. 기본값은 `--role lead` 다. tmux 세션 이름은 리드가 `<폴더>-lead`, 소통이 `<폴더>-comm` 이다. Claude 는 triflux mod 가 이 스킬을 따르라고 알리고, Codex 와 agy 는 진입 프롬프트가 이 파일을 읽게 한다. `/tfx-lead` 는 리드에만 쓴다.
- 후보: Claude `opus` medium, agy `hydrogen` medium, Codex `terra` high 순이다. 리드 후보와 서로 독립으로 고르므로 리드와 소통의 CLI 가 같을 필요가 없다. 순서와 effort 는 실측 전이라 바뀔 수 있다.
- 워커 소유: 문서와 회의 자료 워커는 소통에게, 코드 워커는 리드에게 보고한다. 워커의 보고 대상은 하나다.

## 리드와의 통신

- 리드는 진행 상황을 `.omc/lead/status.md` 에 갱신한다. 소통은 사람이 물을 때 그 파일을 읽고 답한다.
- 리드가 소통에 직접 메시지를 보내는 것은 사람의 결정이 필요할 때와 완료 보고뿐이다.
- 사람이 리드에 직접 지시한 내용은 리드가 `.omc/lead/decisions.md` 에 남긴다. 소통은 답하기 전에 이 파일을 읽는다.

## 사람에게 묻기

- Claude 는 `AskUserQuestion`, Codex 와 agy 는 답변에서 짧은 선택지로 묻는다.
- 결정표의 열은 항목, 선택지, 권고, 근거다. 답은 같은 파일 끝에 기록한다.
- 전제가 바뀌면(예: 호출자가 사라짐) 이미 받은 답도 다시 묻는다.
- 취소할 수 없거나 권한 분류기가 막을 일은 결정표에 따로 표시한다.

## 문서 워커

문서와 회의 자료 워커를 띄우고 관리할 때는 `tfx-lead` 스킬의 "워커 등록" 절과 3절에서 5절까지(부르는 방법, 지시, 결과 받기)를 그대로 쓴다. 지시는 지시서 경로로 보내고, 보고는 결과 파일 경로와 세 줄 요약으로 받는다. 단 지시서의 보고 대상과 보고 명령에는 리드가 아니라 이 소통 세션의 이름을 적는다.
